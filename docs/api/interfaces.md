## Общие договорённости

Они одинаковы для всех шести интерфейсов; ниже у каждого указаны только отличия.

**Ошибки.** Каждая операция возвращает `Result<T>`: значение либо `Error` с кодом и текстом
по-русски. Исключения через границу модуля не выходят. Коды: `InvalidArgument`, `NotFound`,
`AlreadyExists`, `InvalidState`, `IoError`, `ParseError`, `UnsupportedVersion`,
`CorruptedData`, `Cancelled`, `NotImplemented`, `Internal`.

**Владение.** Объектами документа владеет документ. Наружу выдаются указатели «только для
чтения»; они действительны до следующего изменения документа. Для долгой ссылки хранят номер
объекта (`Uuid`), а не указатель. Передача объекта в документ — через `std::unique_ptr`.

**Транзакции.** Каждая изменяющая операция сервиса — одна транзакция: либо выполнена целиком,
либо документ не изменён. Одна операция — один шаг отмены.

**Потоки.** Сервисы и документ вызываются из одного (основного) потока. Исключение —
`IGeometryKernel`, см. ниже.

**Версии.** У каждого интерфейса есть целый номер версии (`k…ApiVersion`). Он увеличивается
при любом несовместимом изменении. Добавление нового метода в конец — совместимое изменение
только внутри одной программы; для дополнений оно несовместимо (см. «Границы библиотек»).

**Границы библиотек.** Сейчас все модули — статические библиотеки одной программы,
поэтому двоичной совместимости между ними не требуется. Интерфейсы используют типы
стандартной библиотеки C++ (`std::string`, `std::vector`); это допустимо, пока дополнения
собираются тем же компилятором, что и программа. Для дополнений, собираемых отдельно
(этап 10), потребуется слой на чистом C либо фиксация компилятора — решение отложено
и записано в рисках.

**Отмена длительных операций.** Операции, которые могут идти дольше секунды, принимают
указатель на флаг отмены (`std::atomic<bool>`). Операция проверяет его между шагами
и возвращает ошибку `Cancelled`; документ при этом не изменён.

**Журнал.** Сервисы пишут в журнал (`core::Logger`) предупреждения и ошибки с именем модуля.
Успешные операции в журнал не пишутся: для них есть журнал изменений документа.

## IDocumentService

1. **Ответственность.** Проект и его документы: создать, открыть, сохранить, добавить
   и удалить документ. Не отвечает за содержимое документов и за формат файла.
2. **Вход и выход.** Пути к проекту, вид и имя документа; возвращает указатель на документ
   либо ошибку.
3. **Ошибки.** `NotFound` — проекта или документа нет; `InvalidArgument` — пустое имя;
   ошибки хранилища передаются без изменений (`CorruptedData`, `UnsupportedVersion`, `IoError`).
4. **Владение.** Сервис владеет проектом. `openProject` и `newProject` уничтожают прежний
   проект: все указатели на его документы становятся недействительными. Окно обязано
   отпустить документ до вызова (так сделано в `MainWindow`).
5. **Потоки.** Только основной поток.
6. **Гарантии.** Неудачное открытие оставляет текущий проект нетронутым. Неудачное сохранение
   оставляет на диске прежнюю версию.
7. **Версия.** `kDocumentServiceApiVersion = 1`.
8. **Границы.** Формат файла подключается через `IProjectStorage` — сервис о нём не знает.
9. **Отмена.** Нет: операции короткие. Понадобится для больших проектов.
10. **Журнал.** Хранилище пишет предупреждение при восстановлении прерванного сохранения.

## IDrawingService

1. **Ответственность.** Лист и основная надпись, слои, 2D-элементы, штриховка, размеры четырёх
   видов; перенос, копия, поворот, масштаб, отражение, обрезка, скругление, фаска, удаление; выноски; правка свойств
   существующего элемента (`editEntity`); виды по 3D-модели (`addModelView`, `updateModelView`) —
   линии вида рассчитывает ядро, сервис чертежа только размещает их. Проверяет входные данные. Не отвечает за правила
   оформления и отрисовку.
2. **Вход и выход.** Документ, координаты в миллиметрах, углы в радианах; возвращает номер
   созданного объекта.
3. **Ошибки.** `InvalidArgument` — нулевая длина, неположительный радиус, не-числа, пустой
   текст, незамкнутый контур штриховки, скругление не помещается; `InvalidState` — отрезки
   параллельны, обрезать нечем; `NotFound` — нет слоя или объекта; `AlreadyExists` — второй
   лист или слой с тем же именем. В `editEntity` свойство, которого у элемента нет, — ошибка
   `InvalidArgument`, а не молчаливый пропуск; при любой ошибке не применяется ничего.
4. **Владение.** Созданные объекты принадлежат документу.
5. **Потоки.** Только основной поток.
6. **Гарантии.** Одна операция — одна транзакция. Операции над несколькими объектами
   (`transformEntities`, `copyEntities`, `removeObjects`, `addRectangle`) либо выполняются
   для всех, либо ни для одного.
7. **Версия.** `kDrawingServiceApiVersion = 1`.
8. **Границы.** Значения параметров по умолчанию заданы в интерфейсе; вызывать сервис следует
   через ссылку на интерфейс.
9. **Отмена.** Нет: операции мгновенные. Понадобится для видов по 3D-модели.
10. **Журнал.** Не пишет.

## IStandardsService

1. **Ответственность.** Список профилей, выдача профиля с применённым наследованием, проверка
   документа. Не меняет документ. Не зависит от окон и 3D-ядра.
2. **Вход и выход.** Документ; возвращает список замечаний: номер правила, критичность, номер
   объекта, объяснение, ссылка на пункт стандарта.
3. **Ошибки.** `InvalidState` — у документа не выбран профиль либо профили наследуют друг
   друга по кругу; `NotFound` — профиль не найден; `ParseError` — профиль повреждён.
   Неизвестный вид проверки в профиле — не ошибка, а замечание-предупреждение.
4. **Владение.** Профиль возвращается копией.
5. **Потоки.** Проверка только читает документ; параллельный запуск нескольких проверок
   допустим, если документ в это время не меняется.
6. **Гарантии.** Результат зависит только от документа и профиля: повторный вызов даёт тот же
   список в том же порядке.
7. **Версия.** `kStandardsServiceApiVersion = 1`. У профиля своя версия; документ её помнит.
8. **Границы.** Профили — файлы JSON; добавление профиля не требует пересборки.
9. **Отмена.** Нет. Проверка 100 000 объектов занимает около 0,1 с.
10. **Журнал.** Не пишет: всё, что нужно знать, возвращается в замечаниях.

## IGeometryKernel

Файл: `geometry/kernel/include/cosmocad/geometry/IGeometryKernel.h`. Реализация: адаптер OCCT,
`geometry/adapters/occt`.

1. **Назначение.** Единственная граница с 3D-ядром: выдавливание, вращение, булевы операции,
   скругление, фаска, перемещение, зеркальная копия (`mirrored`), масса, габарит (`bounds`), зазор
   (`distance`), сетка для показа, проекция для чертежа, разрез (`projectSection` — убирает часть тела
   перед секущей плоскостью, проецирует остаток и возвращает контуры среза для штриховки), STEP и STL.
2. **Входные данные.** Собственные типы CosmoCad: контур (`Profile2D`), плоскость, положение.
3. **Ошибки.** Плохой контур, нулевое расстояние — `InvalidArgument`; пропавшая грань — `NotFound`;
   от тела ничего не осталось — `InvalidState`; сбой внутри OCCT — `Internal` с текстом OCCT.
   Исключения OCCT наружу не выходят.
4. **Владение.** Тело (`ShapePtr`) неизменяемо; каждая операция возвращает новое тело.
5. **Потоки.** Один поток. Параллельный расчёт сетки отключён ради одинакового результата.
6. **Гарантии.** Тело проверяется после каждой операции; некорректное не возвращается (КАЧ-4).
   Одинаковый вход — одинаковое тело и одинаковые имена граней.
7. **Имена граней.** Грань называется по своему происхождению: `E1/side/1000` — боковая грань
   операции `E1` от элемента эскиза 1000, `E1/start`, `E1/end` — торцы, `F1/fillet/1` — скругление.
   Изменённая грань сохраняет имя; части разрезанной грани — `имя`, `имя#2`, … по положению.
   Грани зеркальной копии — `M1/mirror/<прежнее имя>`.
   Ребро задаётся парой имён граней.
8. **Версия.** `kGeometryKernelApiVersion = 4` (добавлена протяжка `sweep`).
9. **Отмена.** Флаг отмены проверяется перед операцией и между гранями при построении сетки.
10. **Журнал.** Не пишет; сообщения OCCT в консоль отключены.

## IModelingService

Файл: `modeling/recompute/include/cosmocad/modeling/IModelingService.h`.

1. **Назначение.** Параметры, эскизы, операции построения детали; перестроение; масса;
   плоскость эскиза на грани (`facePlane`) — чтобы окно перевело точку щелчка в координаты эскиза.
2. **Входные данные.** Документ вида «Деталь». Размеры — формулы (`Expression.h`).
3. **Ошибки.** Формула не читается — `ParseError`; неизвестное имя — `NotFound`; параметры
   ссылаются по кругу — `InvalidState`. Формула проверяется при вводе: плохая в документ не попадает.
   Сбой построения — не ошибка вызова, а состояние операции в отчёте `recompute`.
4. **Владение.** В документе — данные построения. Тело хранится в сервисе и в файл не пишется.
5. **Потоки.** Один поток.
6. **Гарантии.** Одна операция — одна транзакция. `recompute` документ не меняет. Пересчитываются
   только операции, чьи исходные данные (и всё, что до них) изменились. Операция со сбоем
   не останавливает остальные.
7. **Версия.** `kModelingServiceApiVersion = 2`.
8. **Границы.** Геометрию считает только `IGeometryKernel`.
9. **Отмена.** Флаг в `recompute`; при отмене остаётся прежнее тело.
10. **Журнал.** Не пишет.

## IAssemblyService

Файл: `assembly/include/cosmocad/assembly/IAssemblyService.h`.

1. **Назначение.** Компоненты, сопряжения, расстановка, пересечения, состав изделия.
2. **Входные данные.** Документ вида «Сборка»; грани задаются устойчивыми именами.
3. **Ошибки.** Неподходящая грань для сопряжения — `InvalidArgument` сразу при добавлении.
   Противоречивые сопряжения — не ошибка вызова, а список в `SolveReport`.
4. **Владение.** Компонент хранит ссылку на документ детали и своё положение. Тела деталей сборка
   получает через `IPartSource`, поэтому не зависит от модуля моделирования.
5. **Потоки.** Один поток.
6. **Гарантии.** Одна операция — одна транзакция. `solve` меняет документ, только если положение
   хотя бы одного компонента изменилось. Первый компонент закреплён.
7. **Версия.** `kAssemblyServiceApiVersion = 2`.
8. **Ограничение.** Решатель применяет сопряжения по очереди, до 50 проходов. Для типовых
   случаев (ось + плоскость) этого достаточно; общий случай потребует настоящего решателя.
9. **Отмена.** Флаг отмены в `solve` и `checkInterference`.
10. **Журнал.** Не пишет.
