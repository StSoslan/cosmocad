# Архитектура CosmoCad

Результат 2 из раздела 14 исходного ТЗ. Схемы лежат в `docs/uml/`.

## Коротко

CosmoCad — одна программа, разделённая на модули с жёсткими границами («модульный монолит»).
Модули общаются только через опубликованные интерфейсы. Нижние модули ничего не знают
о верхних; это проверяется автоматически при каждой сборке.

Сейчас сделана основа и первая рабочая цепочка для 2D-чертежа:
**нарисовать → проверить оформление по ЕСКД → сохранить → открыть → выгрузить в PDF, SVG, DXF**.
3D, сборки, эскизы с ограничениями и электросхемы спроектированы (интерфейсы и схемы),
но не написаны.

## Пять решений, на которых всё держится

### 1. Документ меняется только через транзакции

Любое действие — это транзакция: набор изменений, который либо применяется целиком, либо не
применяется вовсе. Транзакция запоминает состояние объектов «до» и «после», и отмена просто
возвращает состояние «до».

Что это даёт: отмена всегда точная; сбой посреди команды не оставляет документ «наполовину
изменённым»; журнал изменений ведётся сам. Цена: каждая команда обязана идти через сервис,
писать в документ напрямую нельзя — этого не позволяет сам язык (методы записи закрыты).

### 2. Правила оформления — это данные, а не код

Профиль стандарта — файл `resources/standards/<имя>/profile.json`: форматы листов, рамка,
основная надпись, типы линий, размеры шрифта и список правил с номерами и ссылками на пункты
стандартов. Программа умеет выполнять *виды* проверок («толщина линии в пределах», «элемент
внутри рамки»); какие именно проверки и с какими числами — решает профиль.

В профиле же описана и основная надпись — сетка граф, подписи, заполняемые поля.

Что это даёт: ЕСКД, ISO, DIN, ANSI и стандарт предприятия устроены одинаково; профиль
предприятия наследует ЕСКД и меняет отдельные строки; смена профиля не требует пересборки.
Тексты стандартов в профиль не входят — только числа и номера пунктов.

### 3. Один «список для рисования» на всё

Модуль Graphics превращает документ в сцену — плоский список линий, окружностей, дуг и текста
с уже вычисленными толщинами и штрихами. Экран, PDF, SVG и DXF берут один и тот же список.

Что это даёт: чертёж выглядит одинаково везде; новый формат экспорта — это только запись
списка в файл. Сцена не зависит от Qt, поэтому позже её сможет рисовать OpenGL.

### 4. Геометрическое ядро спрятано за собственным интерфейсом

Модули видят `IGeometryKernel` и собственные типы CosmoCad. Библиотеку OCCT разрешено
подключать только в `geometry/adapters`. Ядро можно будет заменить, не трогая остальное.
Для 2D ядро не нужно: используется собственная 2D-геометрия. 3D целиком идёт через адаптер OCCT
(`geometry/adapters/occt`), и только он видит заголовки OCCT.

### 5. Никакого ИИ — и это проверяется

Программа `scripts/check_no_ai.py` при каждой сборке просматривает файлы сборки и подключения
в коде. Библиотека машинного обучения, обращение к ИИ-сервису или каталог под ИИ ломают сборку.

## Слои

| Слой | Модули | Что знает |
| --- | --- | --- |
| Приложения | `apps/cosmocad`, `apps/cosmocad-cli` | Собирают всё вместе |
| Интерфейс | `ui` | Qt; сервисы; ничего о формате файла и правилах |
| Предметные модули | `drawing`, `standards`, `graphics`, `exchange`, `storage` | Модель документа; друг о друге — только в разрешённом направлении |
| Основа | `core`, `geometry` | Ничего, кроме стандартной библиотеки C++ |

Точные разрешённые связи записаны в `scripts/check_module_boundaries.py` и на схеме 1.

## Ошибки

Через границы модулей исключения не передаются. Каждая операция возвращает `Result`:
либо значение, либо ошибку с кодом и объяснением по-русски. Окно показывает объяснение
пользователю, консольная утилита печатает его и возвращает код 2.

## Потоки

Сейчас вся работа идёт в одном потоке, включая перестроение 3D-модели. Документ не рассчитан на одновременное изменение
из нескольких потоков. Для длительных операций 3D (этап 6) в интерфейсах уже предусмотрен
флаг отмены; сами операции будут выполняться в фоновом потоке над неизменяемыми телами,
а результат — записываться в документ транзакцией в основном потоке.

## Что отличается от исходного ТЗ и почему

| В исходном ТЗ | Сделано | Причина |
| --- | --- | --- |
| Отрисовка на OpenGL 4.5 | Отрисовка средствами Qt (QPainter) | Для 2D-чертежа этого достаточно; сцена уже отделена, OpenGL понадобится для 3D и для очень больших чертежей |
| Файл-контейнер с базой SQLite | Каталог с JSON-файлами и контрольными суммами | База данных внутри архива не работает напрямую (см. РЕШ-6 в `docs/risks.md`); JSON прозрачен и достаточен, пока нет библиотек и поиска |
| Conan 2 | Системные пакеты; `conanfile.txt` приложен | Сборка проверялась на Ubuntu 24.04 с системными пакетами; Conan не проверялся |
| OCCT | Не подключён | Нужен только для 3D (этап 6) |
| PDF в модуле Exchange | PDF в модуле UI | Запись PDF сделана средствами Qt; перенос требует отдельной библиотеки |
| Doxygen и Sphinx | Документы в Markdown | Генерация справочника из кода не настроена |
