# Модель данных и формат файла

Результат 5 из раздела 14 исходного ТЗ. Описывает версию формата **1**.

## Модель данных

```
Проект
└── Документ (чертёж | эскиз | деталь | сборка | схема)
    └── Объект (слой, лист, отрезок, окружность, дуга, текст, размер, …)
```

Схема классов — `docs/uml/02-document-model.md`.

| Понятие | Что это | Где в коде |
| --- | --- | --- |
| Номер объекта | Постоянный уникальный номер (UUID версии 4). Не меняется никогда | `core::Uuid` |
| Объект | Имеет номер, тип, имя, пользовательские атрибуты и собственные поля | `document::Object` |
| Атрибут | Пара «имя — значение». Значение типизировано: логическое, целое, вещественное, строка или ссылка на объект | `document::PropertyValue` |
| Ссылка | Номер другого объекта. Проверка ссылок: `Document::findDanglingReferences()` | — |
| Единицы | Длины хранятся в миллиметрах, углы в радианах. Пересчёт — на входе и выходе | `core/Units.h` |
| Система координат | Начало в левом нижнем углу листа, ось X вправо, ось Y вверх | — |
| История | Стек отмены и повтора в памяти; журнал изменений в памяти | `document::Document` |
| Профиль стандарта | Документ хранит имя и версию профиля, по которому оформлен | `Document::profileId` |

Что из раздела 7 исходного ТЗ ещё не сделано: версии документов (хранится только последнее
состояние); история и журнал не записываются в файл; граф зависимостей, выражения
и перестроение (этап 6).

## Формат `.cosmocad`, версия 1

Проект — **каталог** с расширением `.cosmocad`:

```
пример.cosmocad/
├── manifest.json                 опись проекта
└── documents/
    └── <номер документа>.json    по файлу на документ
```

### manifest.json

```json
{
 "format": "cosmocad",
 "formatVersion": 1,
 "appVersion": "0.1.0",
 "projectId": "0b6c…",
 "projectName": "Пример",
 "documents": [
  {
   "id": "5f1e…",
   "name": "Пластина",
   "kind": "Drawing",
   "file": "documents/5f1e….json",
   "size": 5120,
   "crc32": 2882400001
  }
 ]
}
```

| Поле | Назначение |
| --- | --- |
| `format` | Всегда `cosmocad`. Иначе файл не считается проектом |
| `formatVersion` | Версия формата. Программа отказывается открывать версию новее своей |
| `appVersion` | Версия программы, записавшей файл (для диагностики) |
| `documents[].file` | Путь внутри каталога проекта. Пути с `..` и абсолютные пути отвергаются |
| `documents[].crc32` | Контрольная сумма файла документа (CRC-32) |

```json
    "text": "Фаска", "textHeight": 3.5 }

```

У линейного размера и размера радиуса могут быть необязательные поля допуска: `suffix`
(например, «H7»), `upperDeviation`, `lowerDeviation`.

Новые типы объектов (размеры радиуса и угла, штриховка, выноска) добавлены без смены версии формата:
старые файлы читаются как раньше. Но программа версии 0.1.1 и старше такой файл не откроет —
неизвестный тип объекта для неё ошибка. Это ограничение записано в схеме 7 (правило 3).

Имена полей основной надписи (`titleBlock`) задаёт профиль стандарта; лист хранит только
значения. Поля, которых нет в текущем профиле, при сохранении не теряются.

Общие поля объекта: `type`, `id`, необязательные `name` и `attributes`. Ссылка на объект
в атрибутах записывается как `{"$ref": "<номер>"}`. Порядок объектов в файле — порядок
в документе; он сохраняется.

### Деталь и сборка

Документ «Деталь» хранит данные построения, а не тело: параметры, эскизы, операции, свойства.
Тело при открытии проекта строится заново и получается тем же (`PartFixture.PartSurvivesSaveAndLoad`).

```json
[
  { "type": "Parameter", "id": "…", "name": "длина", "expression": "80" },
  { "type": "Sketch", "id": "…", "name": "Плита", "plane": "XY", "offset": "0", "nextTag": 3,
    "shapes": [ { "kind": "rectangle", "tag": 1, "hole": false, "values": ["0", "0", "длина", "ширина"] },
                { "kind": "circle", "tag": 2, "hole": true, "values": ["отступ", "отступ", "3"] } ] },
  { "type": "Feature", "id": "…", "kind": "extrude", "tag": "E1", "sequence": 1, "suppressed": false,
    "value": "толщина", "sketchId": "…", "cut": false, "reversed": false },
  { "type": "Feature", "id": "…", "kind": "fillet", "tag": "F1", "sequence": 4, "suppressed": false,
    "value": "3", "edges": [["E1/end", "E2/side/1000"]] },
  { "type": "PartProperties", "id": "…", "designation": "КСМ.003.001", "material": "Сталь 45", "density": 7.85 }
]
```

Эскиз на грани вместо `plane` хранит `faceName` — имя плоской грани. Операция с массивом
хранит ещё `pattern`: вид (`linear` или `circular`), число копий, шаг или центр и угол — формулами. Документ «Сборка»:

```json
[
  { "type": "Component", "id": "…", "name": "Палец (1)", "source": "<номер документа детали>",
    "placement": [1, 0, 0, 40, 0, 1, 0, 25, 0, 0, 1, 0], "fixed": false },
  { "type": "Mate", "id": "…", "kind": "concentric", "value": 0.0, "flip": false,
    "first": { "component": "…", "face": "E3/side/1000" }, "second": { "component": "…", "face": "E1/side/1000" } }
]
```

Исполнение детали — объект `Configuration`: имя, `values` (имя параметра → формула), `designation`.
У компонента сборки может быть `explode` — сдвиг в разнесённом виде; у вида по модели — `"exploded": true`.
Технические требования — обычные тексты с именами «Технические требования» (первая строка пункта)
и «Технические требования: продолжение».

Ограничение эскиза — объект `Constraint`: `kind` (`horizontal`, `parallel`, `length`…), `refs` — список
ссылок на элементы (`entity` и `point`: −1 весь элемент, 0 начало, 1 конец, 2 центр), `value`;
у размера-формулы ещё `expression` и `parameters` (номер детали, чьи параметры использует формула).
Эскиз детали, снятый с контура чертежа, хранит `sourceDrawing` и `sourceEntities`.

Блок — объект `BlockDefinition` (имя и `content` — графика в координатах блока); вставка блока —
`BlockRef`: `definition`, `position`, `angle`, `scale` и копия `content`. Операция «протяжка» — `Feature`
с `kind = sweep`, `path` (точки траектории, формулы) и радиусом гиба в `value`.

Знак шероховатости на чертеже — объект `Roughness`: `position` (вершина), `kind` (`any`, `removal`,
`noRemoval`), `parameter` («Ra 3,2»), `quarterTurns`, `textHeight`, для общего знака ещё `others`.

`placement` — матрица 3×4 по строкам (поворот и перенос). Виды сопряжений (`kind`): `coincident`,
`concentric`, `parallel`, `distance`, `angle` (в `value` — градусы), `tangent`. У компонента может быть
`"wholeInSection": true` — на разрезах чертежа он показывается целым. Вид по модели на чертеже — объект
`ModelView`: документ-источник, название вида, место на листе, масштаб, номера своих линий;
у каждого вида `stamp` — отпечаток линий, по которому видно, что модель с тех пор изменилась;
у разреза дополнительно `sectionOnly` (сечение), `section`, `sectionAt` (где проходит секущая плоскость), `label` («А–А»)
и `marks` (номера линий и букв обозначения секущей плоскости); операция «зеркало» хранится как
`Feature` с `kind = mirror`, плоскостью в `axis` и сдвигом в `value`;
и номера размеров, поставленных на этот вид. Откат дерева построения хранится в `PartProperties`
(`rollbackAfter` — номер операции, после которой построение останавливается).

Все эти типы добавлены без смены версии формата: старые файлы читаются как раньше, а программа
версии 0.1 такой файл не откроет и сообщит о неизвестном типе объекта.

### Электросхема

Объекты схемы лежат в документе чертежа рядом с листом:

```json
[
  { "type": "SchElement", "id": "…", "symbol": "resistor", "symbolName": "Резистор", "libraryVersion": "0.1.0",
    "prefix": "R", "designator": "R1", "value": "10 кОм", "position": [80.0, 200.0], "rotation": 0,
    "pins": [ { "name": "1", "at": [-10.0, 0.0] }, { "name": "2", "at": [10.0, 0.0] } ],
    "graphics": [ { "line": [-10.0, 0.0, -5.0, 0.0] }, { "line": [-5.0, -2.0, 5.0, -2.0] } ] },
  { "type": "SchWire", "id": "…", "points": [[90.0, 200.0], [175.0, 200.0]], "junctions": [] },
  { "type": "SchLabel", "id": "…", "position": [50.0, 200.0], "text": "Вход" }
]
```

Элемент хранит копию графики и выводов своего обозначения и версию набора, из которого оно взято:
файл читается без набора и не меняется, когда набор обновили (`Scheme.SchemeSurvivesSaveAndLoad`).
Цепи в файле не хранятся — они вычисляются по расположению проводников и выводов.

### Гарантии формата

| Требование | Как выполнено | Тест |
| --- | --- | --- |
| ФМТ-1. Версия формата | Поле `formatVersion`; более новая версия — отказ с понятным сообщением | `Storage.NewerFormatVersionIsRefusedWithClearMessage` |
| ФМТ-2. Миграции | Цепочка преобразований N → N+1; отсутствующее звено — отказ | `Storage.MigrationChainUpgradesOldFiles` |
| ФМТ-3. Целостность | CRC-32 каждого документа; при несовпадении называется повреждённый файл | `Storage.CorruptionIsDetectedAndNamed` |
| ФМТ-4. Безопасное сохранение | Запись рядом, затем замена; прерванное сохранение восстанавливается | `Storage.InterruptedSaveRecoversPreviousVersion` |
| ПЛ-10. Восстановление | Автосохранение в `<имя>.cosmocad.autosave` каждые 2 минуты | `Storage.AutosaveIsDetectedAndClearedByNormalSave` |
| КАЧ-5. Повреждённые файлы | Случайно искажённые файлы дают ошибку, а не сбой | `Storage.RandomByteDamageNeverCrashes` |

Известные ограничения версии 1:

- Опись `manifest.json` не защищена контрольной суммой: порча её необязательных полей
  может остаться незамеченной.
- Неизвестный тип объекта — ошибка чтения (см. схему 7, правило 3).
- Проект — каталог, а не один файл: его неудобно пересылать. См. ниже.

### Политика совместимости (ФМТ-5)

- Программа читает все версии формата от 1 до своей текущей.
- Программа не читает версии новее своей и сообщает об этом.
- Программа всегда пишет свою текущую версию формата.
- Каждое несовместимое изменение формата увеличивает `formatVersion` на единицу
  и сопровождается миграцией и тестом на файле предыдущей версии.

Пока версия одна, политика не проверялась на практике.

## Отличие от исходного ТЗ

Исходное ТЗ предлагает контейнер с `database.sqlite` и каталогами `geometry`, `previews`,
`libraries`, `attachments`, `metadata`. В версии 1 этого нет, и вот почему:

| Часть | Почему отложена | Когда появится |
| --- | --- | --- |
| Один файл-контейнер | База SQLite не может работать прямо из архива; нужно выбрать один из двух вариантов (РЕШ-6 в `docs/risks.md`) | После решения РЕШ-6 |
| `database.sqlite` | Нужна для поиска и библиотек; для чертежей достаточно JSON | Этап 9 |
| `geometry/` | Двоичные данные 3D-тел | Этап 6 |
| `previews/` | Миниатюры | Этап 12 |
| `libraries/`, `attachments/`, `metadata/` | Нет содержимого | Этапы 9–10 |

Переход к контейнеру будет версией формата 2 с миграцией 1 → 2; механизм миграций готов.
